## 배경

01 문서는 "반려견 명의 편지"와 "자유 대화"를 하지 않는 것으로 정했고, "P0에 조용히 추가하지 않는다"고 적었다.
이 문서는 그 결정을 바꾸자는 제안이다. 채택되면 01의 "하지 않는 것"에서 "반려견 명의 편지"를 빼고 F15로 올린다.

## 기능

보호자가 등록한 반려견에게 편지를 쓰면, LLM이 편지와 반려견 정보를 읽고 **반려견 말투로 짧은 답장**을 쓴다.

```
편지 쓰기 ──▶ POST /pets/:id/letters ──▶ letter_reply 작업 ──▶ 답장 저장 ──▶ 편지함에서 읽기
                 (위기 표현 검사)          (Gemini 텍스트)
```

- 편지 1통에 답장 1통. 이어서 대화하지 않는다 (자유 대화는 여전히 하지 않는 것).
- 답장은 앱 화면에 **"AI가 ○○의 모습을 떠올려 쓴 답장이에요"**를 항상 함께 보여 준다.
- 편지와 답장은 보호자만 본다. 앨범처럼 지울 수 있다.

## 안전장치

슬픔이 큰 보호자가 쓰는 기능이라 아래를 지킨다.

1. **위기 표현이 있으면 답장하지 않는다.** 자해·자살·"따라가고 싶다" 같은 표현이 보이면 반려견 답장 대신 상담 안내(자살예방상담전화 109 등)를 보여 준다. 키워드 검사 + LLM 분류 결과를 함께 쓴다.
2. **답장이 하지 않는 말** (프롬프트와 결과 검사로 막는다)
   - 살아 있다·돌아온다·다시 만날 날을 약속하는 말, 사후 세계를 단정하는 말
   - 보호자를 탓하거나 죄책감을 키우는 말 ("왜 그때…"에 동의하지 않는다)
   - 무언가를 하라고 요구하는 말 (매일 편지 쓰기, 결제 등)
   - 편지에 없는 사실·기억을 지어내는 말
3. **하루 1통**으로 제한한다. 반복 의존을 줄이고 비용 상한도 지킨다.
4. 답장은 3~6문장. 반려견 이름·습관(F09)·보호자가 편지에 쓴 기억만 쓴다.
5. "복원"·"되살렸어요" 같은 표현은 쓰지 않는다 (08 문서 원칙 그대로).

## 데이터·외부 전송

- 편지 본문은 사진보다 민감할 수 있다. 서버 동의 API는 없애기로 해서(PR #77), 편지 화면에 **Google(Gemini)에 편지 글이 전달된다는 안내**를 정적 문구로 보여 준다.
- Gemini 결정 기록의 규칙(유료 키만 사용, 로그 끄기 또는 7일, 55일 남용 감시 보관 안내)을 그대로 따른다.
- 보내는 것: 편지 본문, 반려견 이름·습관. 보호자 이름·이메일은 보내지 않는다.

## API·데이터 (구현)

| API | 내용 |
|---|---|
| `POST /pets/:id/letters` | 편지 저장 + `letter_reply` 작업 등록. 위기 표현이면 작업 없이 `status: crisis` + 상담 안내 `help` |
| `GET /pets/:id/letters` | 편지함 (편지·답장·상태, 최근 순) |
| `GET /letters/:id` | 편지 하나 (답장 기다릴 때 조회) |
| `DELETE /letters/:id` | 편지와 답장 삭제 |

- `letters` 테이블 (`0005_letters.sql`): `user_id`, `pet_id`, `body`, `reply`, `status`(pending·replied·crisis), `job_id`, `replied_at`. 작업이 실패한 pending은 API가 `failed`로 보여 주고 하루 횟수에 세지 않는다
- 작업 `letter_reply` (`app/worker/letter_writer.py`): Gemini 텍스트 모델(`GEMINI_TEXT_MODEL`)에 JSON(`crisis`, `reply`)으로 받는다. 금지 표현이 나오면 한 번 다시 쓰고, 또 나오면 정해진 답장. `MOCK_LETTER=true`(기본)면 정해진 답장
- 위기 표현: API는 키워드(`app/letters.py`의 `CRISIS_KEYWORDS`), 작업자는 LLM 판단. 둘 중 하나라도 걸리면 답장 대신 상담 안내
