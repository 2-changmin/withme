# 03. 3D 파이프라인

핵심 원칙은 **"뼈대 하나와 애니메이션 한 세트를 모든 강아지가 공유"**하는 것이다. 캐릭터마다 하는 일은 표준 뼈대를 그 메시에 맞춰 끼우는 리깅 하나뿐이고, 애니메이션은 다시 만들지 않는다.

```
[사전 제작, 한 번]  표준 뼈대 + 공용 애니메이션 세트                          (황세인)

[보호자마다]
 원본 사진 ──▶ 4면 이미지 ──▶ Meshy GLB ──▶ 메시 정리·관절 추정 ──▶ 관절 보정 ──▶ 리깅 GLB
            (윤승희, Gemini)  (이창민)      (황세인, Blender)      (보호자)     (황세인, Blender)
```

## 1. 4면 이미지 생성 — 윤승희

Image-to-3D는 입력 이미지의 자세를 그대로 재현한다. 앉은 사진을 넣으면 앉은 메시가 나오고, 그 메시는 걷기용 뼈대에 쓸 수 없다. 그래서 3D 전에 **2D에서 자세를 선 자세로 바꾼다.**

**순서**
1. 원본 사진 1~4장을 모두 참조로 넣어 **서 있는 옆모습 기준 1장**을 생성한다.
2. 기준 1장 + 원본을 참조로 **정면, 반대쪽 옆모습, 후면**을 생성한다. ("이 이미지와 같은 강아지" 조건)
3. 4장을 보호자에게 보여 주고 확인받는다. 거절하면 재생성한다 (최대 3회).

4장을 한꺼번에 따로 만들면 사진마다 무늬나 귀 모양이 달라지고, Meshy 결과가 오히려 나빠진다. 그래서 기준 1장을 먼저 만든다.

**프롬프트 초안 (기준 옆모습)**

```
Same dog as in the reference photos. Keep exact fur color, markings,
ear shape, and face. Standing on all four legs, full body side view,
legs straight and slightly apart, tail extended away from the body,
mouth closed, neutral pose. Soft low-poly toy style.
Plain white background, even lighting.
```

**출력 조건** (자동 리깅이 되려면 필요)
- 네 다리가 곧게 서 있고 **다리끼리 붙어 있지 않음** (붙으면 다리를 움직일 때 옆 다리가 끌려감)
- 꼬리가 몸통에서 떨어져 있음, 입은 닫힘, 좌우 대칭
- 흰 배경, 그림자 없음, 1024px 이상 PNG
- 장모종도 털 덩어리가 다리를 덮지 않도록 저폴리 토이풍으로 단순화

**검증할 것**: 같은 강아지로 정면·옆·후면의 무늬 위치가 일치하는가, 앉은 사진만 넣었을 때 다리 모양이 자연스러운가.

## 2. 3D 생성 — 이창민

확인된 4면 이미지를 Meshy에 넣어 GLB를 만든다.

| 항목 | 값 |
|---|---|
| API | `POST https://api.meshy.ai/openapi/v1/image-to-3d` (단일) / 다중 이미지 엔드포인트 (4면) |
| 인증 | `Authorization: Bearer <MESHY_API_KEY>` (Pro 플랜 이상, 무료 플랜은 402) |
| 입력 | 버킷의 4면 이미지 (서명 URL 또는 base64 data URI) |
| 옵션 | `should_remesh: true`, `topology: "triangle"`, `target_polycount: 30000`, `target_formats: ["glb"]`, `should_texture: true` |
| 상태 조회 | `GET /openapi/v1/image-to-3d/{id}` 5초 간격 (또는 `/stream` SSE) |
| 완료 처리 | `model_urls.glb`를 즉시 우리 버킷으로 복사 (Meshy URL은 만료됨) → Meshy 작업 삭제 |
| 실패 처리 | `FAILED`면 1회 재시도. 실패 작업은 Meshy가 크레딧을 환불함 |

`pose_mode`(a-pose/t-pose)는 사람형 옵션이라 쓰지 않는다. 자세는 1단계에서 맞춘다.

**검증할 것**: 단일 옆모습 입력과 4면 입력 중 어느 쪽이 더 닮고 다리가 잘 분리되는가, 실제 소모 크레딧, 평균 생성 시간.

참고 스크립트: [tools/meshy_test.py](tools/meshy_test.py) (로컬 사진 → GLB 다운로드)

## 3. 메시 정리·관절 추정 — 황세인 (Blender)

1. **정리**: 방향 정규화(정면 +Z, 바닥 y=0), 크기 정규화, 중복 정점 병합(Merge by Distance), 면 수 2만 이하로 Decimate
2. **관절 자동 추정** (선 자세가 전제)
   - 바닥 근처를 수평으로 잘라 단면 덩어리 4개 → 네 발
   - 가장 앞쪽 끝 → 코, 가장 뒤쪽 돌출부 → 꼬리 끝
   - 발에서 위로 올라가며 다리 단면 중심을 따라감 → 어깨·골반
   - 척추는 목 시작과 꼬리 시작 사이를 몸통 단면 중심으로 보간
3. 결과를 관절 JSON으로 저장하고 앱에 보여 준다.

**관절 10개**: 코 끝, 목 시작, 꼬리 시작, 꼬리 끝, 앞발, 어깨, 뒷발, 골반, 귀 끝, 귀 뿌리. 왼쪽만 받고 오른쪽은 대칭으로 만든다. 팔꿈치·무릎·척추 중간은 비율로 보간한다.

## 4. 관절 보정 — 보호자 (Unity 화면: 황세인)

- 3D 모델 위에 추정 관절을 점으로 표시하고, 틀린 점만 드래그한다.
- 표면을 누르면 좌표가 피부 위로 찍힌다. 뼈는 몸 안쪽에 있어야 하므로 레이를 쏴서 **들어간 점과 나온 점의 중간**을 관절로 쓴다.
- 안내 문구는 "코 끝을 눌러 주세요"처럼 부위 이름으로 한다.

## 5. 자동 리깅 — 황세인 (Blender)

1. 표준 뼈대를 불러와 관절 좌표에 맞춰 각 뼈의 위치와 길이만 옮긴다. **뼈의 로컬 축(roll)은 유지**한다. 바뀌면 애니메이션이 비틀린다.
2. 메시를 뼈대에 자동 웨이트(Automatic Weights)로 묶는다.
3. 실패하면("Bone Heat Weighting failed") 면 수를 더 줄여 재시도한다.
4. 리깅된 GLB로 내보낸다.

## 6. 표준 뼈대와 공용 애니메이션 — 황세인 (사전 제작)

**표준 뼈대**
- 구성: 루트 · 골반 · 척추 3 · 목 2 · 머리 · 턱 · **귀 좌우 각 2** · **꼬리 4** · 앞다리·뒷다리 좌우 각 4 (어깨·상완·하완·발)
- 기본자세: 네 발로 선 자세, 다리 곧게, 꼬리 뒤로, 정면 +Z
- 뼈 이름·계층·로컬 축을 `skeletonVersion`으로 고정한다. 바뀌면 버전을 올린다.
- 규격 문서: `docs/skeleton-spec.md` (10/28까지)

**공용 애니메이션**: 대기, 반기기(꼬리 흔들기), 쓰다듬기 반응, 걷기·공 쫓기, 앉기, 눕기·자기, 고개 갸웃

- 클립은 **회전값 위주**로 만든다. 그래야 체형이 달라도 같은 클립이 맞는다.
- 골반 상하 움직임 같은 위치 키값은 앱에서 다리 길이 비율로 보정한다. 안 그러면 소형견이 공중에 뜬다.

## 처리 단계 요약

| 단계 | 담당 | 입력 → 출력 | 예상 시간 | 실패 시 |
|---|---|---|---|---|
| 4면 이미지 | 윤승희 | 원본 1~4장 → 선 자세 PNG 4장 | 약 30초 | 재생성 (최대 3회) |
| 3D 생성 | 이창민 | PNG 4장 → GLB | 2~5분 | 1회 재시도 → 사진 모드 안내 |
| 정리·관절 추정 | 황세인 | GLB → 정리된 GLB + 관절 JSON | 수 초 | 보호자가 직접 찍기 |
| 리깅 | 황세인 | 정리된 GLB + 보정 관절 → 리깅 GLB | 10~30초 | 면 수 줄여 재시도 → 관절 재지정 |
