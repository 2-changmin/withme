## 1. 최신 요구사항과 시안 차이

- 최신 #9 완료 조건은 이름·사진 필수, 외부 전송 정적 안내, NativeGallery 사진 선택, 진행률·실패 이유·재시도다.
- **서버 동의 API는 없다.** 동의 저장·조회 API나 동의 버전 필드를 새로 가정하지 않는다.
- 기존 [03 이름·사진](../wireframe/03-profile.svg), [04 사진 이용 안내](../wireframe/04-consent.svg)를 재사용하되, 04의 동의 체크박스·영구 저장을 암시하는 흐름은 최신 이슈와 다르므로 시안 변경 사항으로 구분한다.
- 정적 안내에 Gemini(Google)·Meshy 전송 목적을 표시하고 사용자가 전송을 선택하기 전에는 사진을 외부로 보내지 않는다. 서버 동의 기록이 없다는 이유로 사진 선택 즉시 업로드하지 않는다.
- 04는 ‘안내를 확인하고 사진 올리기’처럼 실제 전송을 명시하는 행동으로 연결한다. ‘사진만 보며 이용하기’는 로컬 사진 이용 경로로 분리하며 생성 API를 호출하지 않는다.
- 이번 구현 범위는 사진이다. 03의 선택적 소리·영상 입력, 앨범·소리 태그, 새 장난감/편지 API는 이번 #9에서 구현하지 않는다.

## 2. 확인한 서버 계약

기준 API: `https://gomagochi-jeahyun.apps.dauai.org`.

| 순서 | 요청 | 입력·결과 | 인증 |
|---|---|---|---|
| 1 | `GET /pets` | 현재 계정의 0~1마리 조회 | 앱 Bearer |
| 2 | `POST /pets` | `{name}` → 201 Pet, 이름 1~30자, 중복 409 | 앱 Bearer |
| 3 | `POST /pets/{petId}/uploads` | `{mimeType, sizeBytes}` → 201 UploadTicket | 앱 Bearer |
| 4 | `PUT {uploadUrl}` | 파일 원문, 티켓의 `headers` 적용 | 앱 Bearer를 별도로 붙이지 않음 |
| 5 | `POST /media/{mediaId}/finalize` | 202 `{jobId}` | 앱 Bearer |
| 6 | `GET /media/{mediaId}` | 상태·오류·새 서명 URL 조회 | 앱 Bearer |

- UploadTicket은 `mediaId`, `uploadUrl`, `method`(기본 PUT), `headers`다. 업로드 성공과 finalize 성공을 별도 단계로 처리한다.
- Media 상태는 `pending → uploaded → ready / rejected`다. 최신 연동 안내는 `uploaded`부터 4면 생성 입력으로 허용하므로 파일 검사 완료를 무조건 기다리는 흐름을 만들지 않는다. UI에는 전송 완료·검사 중·거절을 구분한다.
- 티켓 URL은 안내상 2시간 유효다. 응답에 만료 시각 필드가 없으므로 정확한 시각을 서버 응답으로 받았다고 표시하지 않는다. 서명 URL은 로그·장기 저장에 남기지 않는다.
- 서버 사진 형식은 JPEG·PNG·WebP·HEIC, 장당 10MB·사진 총 10장, 반려견 전체 자료 200MB다. 화면의 첫 생성용 선택은 1~4장으로 제한한다. 원시 OpenAPI의 mimeType은 문자열이므로 실제 허용 형식·상한은 최신 연동 안내와 함께 적용한다.
- 사진 업로드 URL은 외부 저장소 주소다. #8의 앱 API JSON 클라이언트는 호스트가 다르면 거부하므로 파일 전송은 별도 업로더로 구현한다.

## 3. 화면과 상태 흐름

`로그인 성공/미등록 → 이름·사진 준비(03) → 정적 이용 안내(04) → 등록·사진 업로드 → 결과 확인 → #10 연결점`.

- 사진 선택·미리보기·이름 편집은 먼저 로컬에서 수행한다. 이름과 유효한 사진이 없으면 다음 버튼을 켜지 않는다.
- 이름은 공백 정리 후 서버와 같은 길이 기준으로 1~30자를 검증한다. 사진은 파일 크기·실제 읽기·형식·미리보기 가능 여부를 확인한다.
- 사진은 개별 상태를 가진다: 선택됨·티켓 요청·전송 중·finalize 중·전송 완료·검사 완료·거절·실패·취소.
- 각 사진에 진행률·실패 이유·재시도·제거를 제공한다. 이미 완료한 사진을 다른 사진 실패 때문에 다시 보내지 않는다.
- 모든 선택 사진이 유효한 전송 상태인지 확인한 뒤 #10에 전달한다. 실패 사진을 사용자 모르게 제외하거나 4면 생성 요청까지 자동 실행하지 않는다.
- 기존 반려견이 있으면 #8이 확인한 petId를 재사용한다. 이름이 다르다고 기존 정보를 자동 덮어쓰거나 새 반려견을 생성하지 않는다.
- 사진 모드는 로컬 선택 사진 표시까지 연결한다. 앱 재실행 후 장기 보존·확정 캐릭터 복원은 별도 범위로 남긴다.

## 4. 구현 구성

| 구성 | 역할 |
|---|---|
| 등록 화면 제어 | #8 `RegistrationRequested` 연결, 03·04 화면·입력·상태·뒤로가기 |
| 사진 선택기 인터페이스 | Android NativeGallery와 PC 에디터 파일 선택을 분리 |
| 로컬 사진 초안 | 원본 위치·전송용 앱 전용 복사·미리보기·크기·MIME·선택 순서 |
| Pet 등록 클라이언트 | 등록·목록 확인·중복/불명확 응답 처리 |
| Media 클라이언트 | 티켓 발급·finalize·상태 조회 DTO와 오류 처리 |
| 파일 업로더 | JSON 변환 없이 파일 바이트 전송·진행률·취소·시간 제한·해제 |
| 업로드 조정기 | 사진별 상태·중복 탭 방지·완료 유지·단계별 재시도·사용자 변경 시 정리 |

- NativeGallery는 공식 저장소의 Unity 6·대상 Android 지원과 라이선스·버전을 확인한 뒤 도입한다. 이번 준비 단계에서는 설치하지 않는다.
- Android 콘텐츠 URI를 일반 파일 경로로 가정하지 않는다. 네이티브 읽기 기능으로 앱 전용 임시 파일을 준비하고 원본은 변경하지 않는다.
- PC는 에디터 파일 선택을 사용한다. 미리보기는 축소하고 전송 원본과 분리한다. HEIC·WebP는 디코딩 지원을 확인하고 필요 시 변환한 파일의 MIME·바이트 크기를 다시 계산한다. 미지원 형식을 잘못 표시하거나 확장자만 바꾸지 않는다.
- 파일은 가능한 한 `UploadHandlerFile`로 전송해 전체 파일과 디코딩 텍스처를 중복 메모리에 유지하지 않는다.
- 서버 티켓의 HTTPS URL·method·headers를 검사하고 사용한다. 임의 헤더나 앱 토큰을 추가하지 않으며 리다이렉트로 인증 정보를 넘기지 않는다.

## 5. 실패·취소·재시도 원칙

| 상황 | 처리 |
|---|---|
| 선택 취소·권한 거부 | 기존 이름·사진 유지. 다시 선택하거나 사진 모드로 이용 |
| 초과 크기·읽기 실패·지원하지 않는 형식 | 업로드 전 사진별 안내, 유효하지 않은 항목 전송 금지 |
| 반려견 등록 409 | `/pets`로 기존 자료 확인·재사용. 무조건 등록 POST 반복 금지 |
| 등록 응답 유실 | 먼저 `/pets`로 생성 여부 확인. 기존 이름·정보를 자동 변경하지 않음 |
| 파일 전송 실패 | 기존 티켓·단계를 보존해 명시적으로 재시도. 이미 보낸 사진은 유지 |
| 티켓 만료 | 상태를 확인하고 안내. 티켓 재발급·pending 정리 API가 없으므로 무한 신규 예약을 만들지 않음 |
| PUT 성공 후 finalize 실패 | 파일을 다시 보내기 전에 media 상태를 조회하고 finalize 단계부터 복구 가능성 확인 |
| finalize 응답 유실 | media 상태·알려진 jobId로 대조. 중복 실행의 안전성을 서버 계약과 확인 |
| 검사 거절 | `errorCode`를 안내 문구로 바꾸고 교체 경로 제공. 전송 성공을 최종 검사 성공으로 표시하지 않음 |
| 앱 API 401 | #8 세션 갱신 재사용. 쓰기 요청은 실행 여부·멱등성을 확인한 경우에만 제한 재전송 |
| 422·429 | 형식/용량·개수 제한 안내. 자동 요청 반복 금지 |
| 화면 이탈·로그아웃 | 전송 취소·기존 사용자 결과 반영 방지·임시 파일 정리. 서버 자료를 삭제하는 API는 가정하지 않음 |

서버에 업로드 목록·미완료 예약 취소·티켓 갱신 API는 현재 확인되지 않는다. 따라서 앱 강제 종료 이후 모든 미완료 업로드를 복구한다고 약속하지 않는다. 보존할 로컬 재개 정보는 사용자별 petId·mediaId·단계 등 최소 식별자이며 원본·서명 URL·토큰은 포함하지 않는다.

## 6. 진행 순서와 검증

1. DTO·상태·요청 계약 및 티켓/finalize 재시도 조건을 먼저 정리한다.
2. PC 파일 선택·초안·사진별 상태와 03·04 화면을 구현한다.
3. Pet·Media 클라이언트와 파일 업로더를 만들고 #8 진입점에 연결한다.
4. 목 전송으로 정상·중간 실패·완료 유지·취소·중복 탭·401·429·URL 만료·finalize 실패를 검증한다. 파일 업로드에 앱 Bearer가 붙지 않는지도 검사한다.
5. 로컬 테스트 HTTP 서버 등으로 원본 바이트·Content-Type·업로드 진행·실제 취소를 검증한다. 외부 계정 생성 없이 테스트할 수 있게 분리한다.
6. 초대된 테스트 계정과 테스트용 사진이 준비되면 실제 등록→티켓→PUT→finalize→상태 조회를 확인한다. 실제 보호자 자료나 유료 생성 API를 테스트에 사용하지 않는다.
7. Unity PC 화면을 사용자 확인한다. NativeGallery·권한·URI·모바일 메모리는 후속 Android 확인 대상으로 기록하며 매 수정마다 APK를 만들지 않는다.

## 8. 구현·검증 기록 — 2026-10-30

### 실행과 변경

- `Assets/Withme/Scenes/Start.unity`에서 로그인 후 미등록 사용자는 이름·사진 화면으로 이동한다. 기존 사용자는 상태 확인 화면의 ‘사진 등록 이어가기’로 진입하며 기존 Pet 이름을 덮어쓰지 않는다. 확정 전 3D 방에 진입하지 않는다.
- 이름은 공백 제거 후 Unicode 문자 1~30자다. 사진은 1~4장·장당 10MB, 파일 내용으로 MIME을 판별하고 앱 임시 복사본과 축소 미리보기를 사용한다. 원본 파일은 수정·삭제하지 않는다.
- 선택·미리보기·로컬 사진 모드는 네트워크를 사용하지 않는다. 전송 안내의 ‘안내를 확인하고 사진 올리기’에서만 Pet 확인/등록→티켓→파일 PUT→finalize→미디어 조회를 수행한다.
- `RegistrationApi`는 #8 세션을 사용한다. GET 401은 갱신 후 한 번 재요청, 다시 401이면 세션을 지운다. POST는 401에 자동 재전송하지 않는다.
- `UnityFileUploader`는 `UploadHandlerFile`과 티켓 헤더만 사용한다. 앱 세션을 받지 않으며 앱 Bearer를 덧붙이지 않는다. 티켓 자체의 저장소 전용 인증 헤더는 계약대로 허용한다. 리디렉션은 금지한다.
- 완료된 사진은 다시 보내지 않는다. PUT 이후 finalize의 명확한 거절은 파일 재전송 없이 재시도한다. finalize 응답 유실·알려진 jobId는 GET으로 상태를 대조하고, 계속 pending이면 중복 finalize 대신 결과 확인 안내를 유지한다.
- `uploaded`는 ‘전송 완료·검사 중’, `ready`는 준비 완료, `rejected`는 교체 안내다. #10 연결점은 `RegistrationFlow.UploadsReady`, `PetId`, `CompletedMediaIds`다. 생성 API는 호출하지 않는다.
- NativeGallery 1.9.5를 Git 커밋 `6fdfae30629814b22b971453d87665d10e1c2ed4`로 고정했다. Android/iOS는 NativeGallery, PC 에디터는 파일 선택창이다. PC에서는 JPEG/PNG 미리보기만 지원하며 WebP/HEIC는 기기 디코더 확인 대상이다. PC의 안전한 디코딩 상한은 한 변 8192·3200만 픽셀이다.

### 재현과 한계

1. Unity에서 Start 씬을 연다. 실제 연결은 기본값이며 초대된 이메일로 로그인한다.
2. 외부 전송 없는 화면 확인은 LoginFlow의 `Use Demo Responses`를 Play 전에 켜고 임의 이메일·코드 `123456`을 입력한다. 화면에 목 모드 표시가 나온다. 확인 후 Play를 종료하고 옵션을 끈다.
3. JPEG/PNG 1~4장을 선택하고 이름·사진 필수 조건, 로컬 사진 모드, 전송 안내, 진행/완료 화면을 확인한다. 서버 장애/재시도는 `unity/tools`의 검증 도구로 재현한다.
4. 실기기에서는 사진 권한 거절·선택 취소·복귀·HEIC/WebP·느린 네트워크·전송 취소를 별도로 확인한다. APK 파일은 없다.

임시 초안·서명 URL은 메모리와 앱 임시 폴더에서만 사용한다. 화면 이탈만으로 초안은 유지되고 로그아웃·사용자 변경·씬 종료 시 정리한다. 앱 강제 종료 후 초안 복원은 구현하지 않았다. OS가 회수하지 않은 임시 복사본은 남을 수 있으므로 영구 저장 자료로 취급하지 않는다. 미완료 예약 취소·티켓 재발급 API가 없어 선택 삭제는 서버 예약을 삭제하지 않으며 재선택은 서버 사진 상한에 영향을 줄 수 있다. finalize가 계속 pending인 경우의 복구는 서버 계약 확인 대상이다. NativeGallery 모바일 분기와 기기 동작은 PC 검증만으로 완료 처리하지 않는다.
