# 이슈 단위 작업 흐름

전체 목표를 한 번 전달하더라도 구현·검증·기록은 이슈 단위로 나눈다. 외부 이슈 번호가 아직 없으면 [작업 계획](work-plan.md)의 `Uxx`를 임시 식별자로 사용한다. 계획표 작성은 GitHub 이슈 생성이나 기능 구현 완료를 뜻하지 않는다.

## 진행 순서

1. 해당 이슈와 선행 작업, 현재 브랜치·변경 사항을 확인한다.
2. 실제 코드·패키지·API·샘플 에셋을 확인하고, 필요한 파일과 완료 조건을 정한다.
3. 이슈 범위만 구현하고 컴파일·관련 테스트·동작을 검증한다.
4. 변경 내용과 검증 근거를 이슈 기록에 남긴다. 계획표 상태를 갱신한다.
5. 사용자는 에디터·실기기에서 확인한다. 결과가 실패면 같은 이슈를 수정한다.
6. 사용자 확인 후 병합한다. 확인 대기 중인 독립 이슈는 계속 진행할 수 있다.

상태는 `대기 → 진행 중 → 구현 완료·확인 대기 → 사용자 확인 완료 → 병합 완료`로 기록한다. 외부 의존성 때문에 진행할 수 없으면 `차단`으로 표시하고 필요한 입력을 적는다. 검증 실패는 구현 완료로 처리하지 않는다.

## 이슈·검증 기록 양식

실제 이슈 본문에 아래 양식을 사용한다. 로컬에서만 진행하면 `unity/docs/issues/Uxx-작업명.md`로 저장하고 계획표에서 연결한다. 아직 시작하지 않은 이슈 기록을 미리 대량 생성할 필요는 없다.

- 브랜치:

## 스킬과 도구 구성 계획

| 구성 | 역할 | 현재 상태 |
|---|---|---|
| Unity 에디터 스킬·CLI 또는 MCP | 씬·프리팹 수정, 콘솔·화면·테스트 확인 | 공식 플러그인 0.1.8-beta, CLI 1.0.0-beta.14, Pipeline 0.9.1-exp.1 연결 검증 완료. MCP 이름 충돌 도구 제외 |
| 프로젝트 작업 진행 스킬 | 이슈 의존성·진행 기록·재개 | 작성 예정 |
| API·3D 연결 검증 스킬 | DTO·목 응답·GLB·뼈대 연결 검증 | 작성 예정 |
| 빌드·인수 확인 스킬 | 관련 검사·APK·수동 확인 절차 제공 | 작성 예정 |

2026-10-28 [Unity 공식 플러그인](https://github.com/Unity-Technologies/unity-agent-plugin)과 CLI·Pipeline 연결을 확인했다. CLI는 `C:\Users\rksek\AppData\Local\Unity\bin\unity.exe`, Codex MCP 서버 이름은 `unity`이며 `withme_frontend` 경로로 고정했다. 기존 프로세스에는 새 PATH가 반영되지 않을 수 있어 CLI 절대 경로를 사용한다. MCP 설정을 읽는 새 Codex 세션에서 도구 노출을 확인한다. 베타 MCP의 중복 이름 도구는 제외했으며, 이 기능들은 CLI의 전체 명령 이름으로 호출한다. 실제 에디터 상태·콘솔·MCP C# 조회 결과와 제외 목록은 [U01 연결 기록](issues/U01-editor-connection.md)에 남겼다. 프로젝트 전용 스킬은 별도 작업이며 공통 규칙은 [AGENTS.md](../AGENTS.md)에 유지한다.
