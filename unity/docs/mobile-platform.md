# 모바일 구현·빌드·배포 명세

2026-10-29 작성. 상위 [아키텍처](../../docs/02-architecture.md)의 Android APK 직접 배포를 구체화한다. 이 문서는 구현 기준이며 설정 적용·빌드 성공·실기기 검증을 의미하지 않는다.

## 앱 구성과 대상

- 실제 프로젝트는 `unity/withme_frontend/`, 에디터는 `6000.0.76f1`로 고정한다.
- 로그인·등록·메뉴를 포함한 앱 전체를 Unity로 구현한다. UI는 uGUI + TextMeshPro, 강아지·방·미리보기는 URP 3D로 구성한다.
- Unity에서 Android 실행 앱을 직접 빌드한다. 별도 Kotlin·Flutter·React Native 앱에 Unity를 삽입하는 Unity as a Library 구조는 채택하지 않는다. OS 기능은 필요한 범위의 네이티브 플러그인·브리지로 호출한다.
- 1차 대상은 Android ARM64 기기이며 최대 10명 비공개 파일럿에 APK로 직접 배포한다. Google Play 등록·AAB 배포는 이번 범위에 포함하지 않는다.
- iOS는 후속 선택 범위다. Apple 개발자 계정·Mac/Xcode·iOS 플러그인 지원·실기기가 준비되면 별도 빌드와 TestFlight 검증을 진행한다. Android 통과를 iOS 통과로 간주하지 않는다.

## 시작과 화면 구성

- 시작 흐름은 `앱 초기화 → 인증·등록 상태 확인 → 목적 화면`으로 구성한다. 제품용 시작 씬과 포함 씬 목록은 U03 구현 시 확정한다. 현재 SampleScene·SetupValidation을 제품 진입 화면으로 취급하지 않는다.
- 인증이 유효하고 강아지 등록·최종 확정이 끝났으면 매번 3D 메인으로 진입한다. 이전 메뉴·사진 화면을 첫 화면으로 복원하지 않는다.
- 인증 만료 시 로그인 후 상태를 다시 확인한다. 미등록은 등록 흐름, 생성 중은 기존 작업 조회, 미확정은 모습·움직임 확인으로 연결한다. 동의 거부·생성 실패의 사진 모드 경로는 유지한다.
- 메인에는 쓰다듬기·부르기·장난감 등 상호작용과 메뉴 진입점만 둔다. 그 외 기능은 통합 메뉴에 배치한다. 상세 흐름은 [와이어프레임](wireframe/README.md)을 따른다.

## 모바일 화면과 입력 기준

- 최초 구현 기준은 세로 고정(Portrait)이다. SVG의 `390 × 844`는 UI 배치 기준이며 실제 렌더링 해상도를 고정하지 않는다. 화면 방향은 기존 시안에서 미확정이었으며 이 문서에서 구현 기본값을 정한다. 사용자 시각 확인은 별도로 수행한다.
- 루트 Canvas는 Screen Space Overlay, CanvasScaler는 Scale With Screen Size, 기준 해상도 `390 × 844`, Match `0.5`로 시작한다. 앵커·레이아웃을 사용하고 비율별 실기기 결과에 따라 보정한다.
- 배경·3D 화면은 전체 화면을 사용한다. 버튼·입력·문구는 `Screen.safeArea` 안에 배치하고 화면 크기·안전 영역 변경 시 다시 계산한다. SVG 상태 표시줄·하단 제스처 막대를 앱 UI로 복제하지 않는다.
- 긴 질문·메뉴·입력 화면은 스크롤을 지원한다. 키보드가 열리면 현재 입력칸과 다음 버튼에 접근할 수 있어야 한다. OS 글자 확대·긴 이름에서 잘림 여부를 확인한다.
- EventSystem과 InputSystemUIInputModule을 사용한다. UI가 터치를 소비하면 뒤의 3D 상호작용을 실행하지 않는다. 강아지 터치는 카메라 레이캐스트로 처리한다.
- 부르기·제출·생성 요청은 중복 탭을 방지한다. 첫 버전에서 다중 터치 제스처는 요구하지 않는다.
- Android 뒤로가기는 `키보드/팝업 닫기 → 메뉴 닫기 → 화면의 이전 단계` 순서로 처리한다. 제출된 서버 작업을 취소하거나 등록 데이터를 삭제하지 않는다. 루트에서는 OS 뒤로가기 동작으로 앱을 백그라운드로 보낼 수 있게 한다.

## 기기 기능·권한·저장

| 기능 | 구현 기준 | 확인할 실패·취소 경로 |
|---|---|---|
| 사진·영상·음원 선택 | 상위 설계의 NativeGallery·NativeFilePicker를 우선 검토한다. Unity 6·대상 Android·선택기 지원을 확인한 버전을 고정한 뒤 도입한다. OS 선택기와 필요한 최소 권한을 사용한다. | 선택 취소·권한 거부·접근 철회·지원하지 않는 형식·과대 파일 |
| 선택 파일 읽기 | Android의 콘텐츠 URI를 일반 파일 경로로 가정하지 않는다. 플러그인의 읽기 기능으로 필요한 데이터를 앱 전용 임시 저장소에 복사하고 업로드 후 정리한다. | 읽기 실패·공간 부족·임시 파일 삭제·앱 종료 |
| 녹음 | 첫 버전은 기존 녹음 파일 선택이 기본이다. 앱 내 직접 녹음을 구현할 때만 마이크 권한을 요청한다. | 권한 거부 시 파일 선택·무음 이용 유지 |
| 인증 토큰 | Android Keystore로 보호되는 키를 이용한 암호화 저장을 사용한다. 구체적인 라이브러리·브리지는 U04에서 지원 버전·유지보수 상태를 확인해 고정한다. PlayerPrefs·평문 파일에 저장하지 않는다. | 만료·갱신 실패·로그아웃·계정 변경 시 삭제 및 재인증 |
| GLB·이미지 캐시 | 앱 전용 저장소에 사용자·캐릭터·버전별로 구분한다. 다운로드 완료 후 교체하며 손상·삭제 시 재다운로드한다. | 계정 전환 시 이전 사용자 자료 노출 금지·캐시 부족·서명 URL 만료 |

권한은 해당 기능을 선택한 시점에 요청한다. 기능과 무관한 카메라·마이크·전체 저장소 권한을 시작 시 일괄 요청하지 않는다. 플러그인은 현재 설치·검증 완료 상태가 아니다.

## 통신과 앱 중단·복귀

- 배포 앱은 HTTPS API와 Supabase 인증·서명 URL을 사용한다. 서버 API·비밀 키·로그 기준은 [연결 규격](integration.md)을 따른다.
- 개발 기기에서 PC 서버를 쓸 때는 LAN 주소 또는 `adb reverse`를 사용한다. 개발용 HTTP 허용이 필요하면 개발 빌드에만 한정하며 배포 설정과 분리한다.
- 앱 일시 중단 시 상호작용·오디오·불필요한 작업 조회를 멈춘다. 백그라운드에서 Unity가 계속 실행된다고 가정하지 않는다.
- 생성 작업 식별자와 재개에 필요한 최소 상태를 보존한다. 복귀·프로세스 재시작 후 인증을 확인하고 서버 상태를 재조회한다. 서버 생성 작업은 앱 종료 때문에 새로 만들지 않는다.
- 업로드 중단은 완료 여부를 서버와 대조한 뒤 재시도한다. 최초 버전은 OS 백그라운드 업로드 서비스를 전제로 하지 않는다. 목 응답과 실제 서버 통과를 구분한다.

## Android 빌드 기준

| 항목 | 기준 / 상태 |
|---|---|
| 도구 | Unity Hub에서 같은 에디터의 Android Build Support·SDK & NDK Tools·OpenJDK 설치. 2026-10-29 사용자 라이선스 동의 후 CLI로 설치 완료. APK·기기 검증 결과는 [#7 기록](issues/U02-issue-7-character-playback.md)에서 관리 |
| 대상 | Android / IL2CPP / ARM64. 현재 프로젝트 설정과 일치 |
| 최소 Android | 현재 설정 API 23. 설치할 네이티브 플러그인·SDK·기준 기기가 더 높은 버전을 요구하면 근거를 기록하고 변경 |
| Target API | 현재 Automatic. 첫 APK에서 실제 선택된 SDK·Target API를 빌드 기록에 남긴다. 스토어 배포를 추가하면 당시 요건을 별도 확인 |
| 앱 식별자 | 현재 템플릿 값. 첫 배포 전 팀 소유의 고유 식별자를 확정하고 고정한다. 임의로 소유 도메인을 가정하지 않는다 |
| 버전 | 표시 버전과 Android versionCode를 기록한다. 배포 업데이트마다 versionCode 증가 |
| 개발용 구성 | Android Development Build, 로그·진단 허용, 목/개발 API 구성 명시. 인증정보·개인자료는 로그 제외 |
| 파일럿 구성 | Development Build·Script Debugging 해제, 실제 HTTPS 환경과 고정 서명 사용. 개발용 인증 우회·목 사용 여부를 배포 전 점검 |
| 포함 씬 | 제품 시작 씬을 첫 번째로 지정. 검증 전용 SetupValidation은 파일럿에서 제외 |
| 서명 | 개발은 디버그 서명 가능. 파일럿은 팀이 보관하는 전용 keystore 사용. 업데이트도 같은 식별자·서명 유지. 키·비밀번호는 Git 제외 |
| 산출물 | APK와 빌드 로그. `Builds/Android/<version>-<versionCode>/` 아래 저장하고 Git에 커밋하지 않음 |

빌드 순서는 `모듈 준비 → Android 빌드 프로필 생성·전환 → 식별자·버전·씬·API 환경·서명 확인 → APK 빌드 → 기기 설치·실행 → 검증 결과 기록`이다. 실행 가능한 명령 자동화는 실제 Android 도구 설치 후 확정한다.

## 배포·검증 완료 조건

- 첫 APK는 U02에서 샘플 GLB·공용 클립 동작 확인용으로 만든다. 제품 흐름 통합·파일럿 배포 확인은 U13, 성능 측정은 U14에서 수행한다.
- APK 전달 경로는 팀이 정한 접근 제한 공유 위치를 사용한다. 구체적인 서비스·업로드 담당자는 첫 배포 전에 기록한다. 앱 내 비밀 키·실제 보호자 자료를 포함하지 않는다.
- 배포 기록에 커밋, Unity/SDK/NDK/JDK 버전, API 환경·목 여부, 포함 씬, 식별자, 버전·versionCode, APK 경로·SHA-256, 서명 구분을 남긴다. 서명 비밀번호는 기록하지 않는다.
- 기종·Android 버전과 함께 설치·업데이트·첫 실행·재실행, 화면 비율·노치·키보드·뒤로가기, 파일 선택·권한 거부, 터치, 앱 중단·프로세스 종료 후 복구를 확인한다.
- 배포용 구성에서 GLB·셰이더·한글·JSON 변환·네이티브 플러그인을 실제 기기로 확인한다. 에디터 통과만으로 IL2CPP 빌드의 동작을 보장하지 않는다.
- 기능 확인 후 기준 기기에서 30fps·터치 반응 150ms·방 진입 5초를 측정한다. 기준 기종과 측정 조건은 U14에서 확정하며 미측정 항목을 통과로 표시하지 않는다.
- 자세한 인수 항목은 [검증 명세](verification.md)를 따른다. 이 문서 작성 시점에는 APK·기기 검증 결과가 없다.
