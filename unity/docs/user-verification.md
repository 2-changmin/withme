# 사용자 검증 목록과 이슈 판정

2026-10-31, `unity` 브랜치 일괄 구현 기준. 자동 검사 근거는 [인수 기록](../../docs/batch-acceptance.md)과 [검증 결과 JSON](../../docs/batch-validation-results.json)에 있다. 아래 항목은 자동 검사 통과와 별개로 확인해야 한다.

## 지금 PC에서 확인할 것

Unity 6000.0.76f1로 `withme_frontend`를 연다. 동작 비교는 `Assets/Withme/Scenes/StandardRigValidation.unity`, 제품 흐름은 `Assets/Withme/Scenes/Start.unity`다. [목 실행 안내](standard-rig-validation.md)를 따른다.

| 확인 | 방법·합격 기준 | 관련 이슈 |
|---|---|---|
| [ ] 세 체형의 대기·걷기 | 검증 씬의 Idle/Walk와 공용/모델별 비교를 눌러 몸 길이·다리 길이가 유지되는지, 발이 과하게 미끄러지거나 몸통이 늘어나지 않는지 본다. | #2, #7, #52 |
| [ ] 반응과 자세 17개 | Greet, 쓰다듬기 3종, Trot, 앉기/일어나기, 엎드리기/수면/깨기, HeadTilt를 확인한다. 특히 몸통·귀·다리의 늘어남, 털 돌출, 바닥 침범, 동작 전환을 본다. | #3, #5, #52 |
| [ ] 자동 관절 추정의 자연스러움 | 세 입력 중 적어도 두 개에서 코·목·귀·꼬리·네 발의 점이 보정 없이 그럴듯한지 확인한다. 현재 PC의 `Temp/batch/rigged/<모델>.blend`에 있는 Landmarks도 참고할 수 있다. | #4 |
| [ ] 점 수정 조작성 | 걸음 확인→‘움직임이 어색해요’에서만 수정 화면이 열리고, 회전/확대 후에도 점을 잡기 쉬운지, 좌우 대칭·초기화·취소·재제출이 자연스러운지 본다. | #11 |
| [ ] 외형 수정 결과 | ‘외형이 어색해요’에서 원본과 비교한다. 귀·꼬리·다리/몸/머리·색을 조절한 뒤 걷기를 다시 보고, 취소 시 이전 모습이 돌아오는지 확인한다. 조절 화면에서 최종 확정되지 않아야 한다. | #12 |
| [ ] 질문과 문구 | 한 화면 한 질문, 4개 순서, 이전 답 유지와 마지막 함께하기 버튼을 확인한다. 안내 문구·글자 크기·화면 넘침도 본다. | #12 |
| [ ] 방·메뉴·소리 | 부위별 쓰다듬기, 불러보기, 장난감 복귀, 휴식/수면을 확인한다. 상호작용 외 기능이 단일 메뉴에 있고 소리 끄기·사진 모드·즉시 나가기가 즉시 동작하는지 듣고 본다. | #13 |
| [ ] 실패/중단/재접속 | 나중에 확인하기→이어하기, 준비 중 종료·재시작, 사진 모드, 로그아웃/계정 변경 시 이전 강아지와 소리가 남지 않는지 확인한다. | #8, #11~13 |

현재 모델 경고는 **m1 13개 / m2 5개 / m3 18개**다. 세 모델 모두 품질 미승인이므로 일반 경로에서는 확정·방 진입을 차단한다. 방/질문 기능만 살펴보는 독립 검사에는 `verify-rig-view.cs`의 `Preferences`·`RoomPreview`·`Room` 진입점이 있으며, 승인된 계약 목을 사용한다. 이 경로를 실제 모델 품질 승인으로 해석하지 않는다. 현재 PC의 무시되는 `Temp/batch` 작업 정보가 필요하며 새 체크아웃에서는 로컬 목/HTTP 검증 준비부터 재생성한다.

정면 17장·옆모습 6장 캡처는 현재 PC의 `withme_frontend/Temp/batch/review/`에 있다. 특히 m3의 SitDown/StandUp 바닥·접지, m1의 앉기/반응, 흰 모델의 털 주변을 우선 확인한다. 스크린샷은 Git에 포함하지 않는다.

## 실제 연동 준비 후 확인할 것

| 확인 | 필요한 준비·검증 | 관련 이슈 |
|---|---|---|
| [ ] 실제 이메일 로그인 | 허용된 테스트 이메일로 코드 수신/재전송·오류·만료/갱신·로그아웃을 확인한다. 목 코드 123456은 실제 로그인 검증이 아니다. | #8 |
| [ ] 실제 준비 메시·리깅 | 정규화된 준비 메시와 관절이 같은 공간인지 확인하고, 실제 작업자 성공/실패/needs_review·중단 재개·중복 방지를 검사한다. | #3, #11, #17 |
| [ ] 실제 확정·습관 저장 | #24 API가 준비되면 새 버전 저장, 명시적 확정 전 방 차단, 습관 저장, 재로그인/재시작 시 확정 강아지 3D 메인 진입을 확인한다. 이전 메뉴/사진 화면이 첫 화면으로 복원되면 안 된다. | #12, #24 |
| [ ] Android 기기 | APK 재개 후 갤러리/권한·한글·셰이더·터치·백그라운드 복귀·기기 보안 토큰 저장을 확인한다. | #7, #8, #15 |
| [ ] 기준 폰 성능·관문 | 기준 기종에서 대기/걷기 30fps, 터치 반응 150ms, 방 진입 5초를 측정하고 사진→4면→실제 GLB→리깅→폰까지 시연한다. | #7, #15, #52 |

APK/실기기는 기존 보류 지시를 유지했다. 기준 폰·서명 보관 담당·파일럿 APK 전달 위치도 확정해야 한다.
