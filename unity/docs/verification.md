# 검증과 사용자 인수

Codex는 구현과 기본 검증을 수행한다. 사용자는 화면·조작·Android 실기기 동작을 확인한다. 성능 측정·최적화는 기능 인수 이후 마지막 단계에서 수행한다.

## 이슈별 기본 검증

- 관련 C# 컴파일 오류를 확인한다. 기존 오류와 새 오류를 구분한다.
- 좌표 계산·상태 전환·응답 변환 등 핵심 로직에는 필요한 EditMode 테스트를 실행한다. 씬·컴포넌트·비동기 흐름은 관련 PlayMode 테스트 또는 에디터 재현으로 확인한다.
- 문서·단순 표현 수정마다 형식적인 테스트를 추가하지 않는다. 변경의 실패 위험을 직접 확인하는 검증을 선택한다.
- 정상 동작 외에 해당 기능의 오류·취소·중복 입력·재시작을 확인한다.
- 새 콘솔 오류, 누락 참조·에셋, 화면 전환 후 잔류 재생·이벤트를 확인한다.
- 실행 도구가 없으면 미실행 이유와 재현 방법을 기록한다. 파일 검사만으로 Unity 컴파일·실행 통과를 보고하지 않는다.

## APK와 실기기 확인

앱 구성·화면 대응·기기 기능·빌드 프로필·서명·배포 기록은 [모바일 구현·배포 명세](mobile-platform.md)를 따른다.

기능 확인 지점마다 APK를 제공한다. 매 이슈마다 전체 Android 빌드를 반복할 필요는 없지만, 네이티브 플러그인·권한·파일 선택·보안 저장소 변경은 실기기 확인 대상으로 남긴다.

1. 실제 프로젝트의 에디터 버전과 Android 모듈·SDK·NDK·JDK 준비 상태를 확인한다.
2. 선택한 빌드 설정·포함 씬·패키지 식별자·버전·목/실서버 구성을 기록한다. 서명 키·비밀번호는 저장소에 넣지 않는다.
3. APK를 빌드하고 성공 로그·산출물 경로·빌드 식별자를 이슈에 남긴다. 산출물은 소스 Git에 커밋하지 않는다.
4. 사용자는 기기에서 설치·실행하고 이슈의 직접 확인 순서를 따른다.
5. 기종·Android 버전·확인한 APK와 통과·실패 결과를 기록한다. 확인하지 않은 항목은 미확인으로 유지한다.

실기기의 `localhost`는 PC 서버 주소가 아니다. 개발 API 접근 주소·연결 방식을 확인한다. 로컬 개발을 위한 설정과 배포 보안 설정을 구분한다.

CLI·MCP 연결 시 실제 `unity/withme_frontend/`가 대상인지 확인한다. 같은 프로젝트를 에디터에서 열어 둔 채 별도 batchmode를 실행하지 않는다. 검증 명령은 설치된 Unity와 Test Framework에 맞춰 확정한 뒤 이슈에 기록한다.

## 기능 인수 시나리오

상위 [인수 테스트](../../docs/08-quality-ethics.md)의 통과 기준을 따른다. 아래는 앱에서 확인할 대상이다. 권한·접근 차단 등 서버 측 통과는 서버 담당자의 별도 근거가 필요하다.

| ID | 직접 확인할 내용 |
|---|---|
| T01 | 앉은 사진 1장·소리 없이 시작해 캐릭터 또는 사진 모드까지 이용 |
| T02 | 잘못된 형식·과대 파일 거부, 기존 자료 보존 |
| T03 | 생성 중복 탭·앱 재시작 시 기존 작업 복구; 서버의 중복 처리 검증 결과도 확인 |
| T04 | 4면 재생성·사진 모드, 자동 확정 없음 |
| T05 | 관절 재지정, 확정 전 방 진입 차단 |
| T06 | A1~A5 연속 실행·도중 나가기, 상태·소리 정리 |
| T07 | 소리 미등록 시 무음 이용, 가짜 짖음 없음 |
| T08 | 기기 시계 변경에도 상태 악화·출석 압박·알림 없음 |
| T09 | 계정 전환 시 이전 사용자 자료 미노출; 서버 접근 차단 결과는 별도 확인 |
| T10 | 생성 업체 장애 시 실패 안내·사진 모드·앨범 이용 |
| T11 | 재로그인 후 확정 캐릭터·GLB·설정 복원 |

원본 기록·편집 소리·AI 캐릭터 구분, 동의 거부 시 사진 모드·앨범, 음소거·동작 줄이기·즉시 나가기도 확인한다. 실제 보호자 사진의 외부 전송은 상위 개인정보 조건을 충족한 뒤 진행한다.

## 마지막 성능 검사

U14에서 기준 기종과 측정 조건을 먼저 기록한다. 측정 전에는 수치 달성으로 표시하지 않는다.

| 항목 | 상위 PRD 목표 | 기록할 조건 |
|---|---|---|
| 프레임률 | 30fps | 모델·장면·해상도·빌드 종류·측정 구간·발열 상태 |
| 터치 반응 | 150ms | 입력부터 시각 반응까지 측정 방법·반복 결과 |
| 방 진입 | 5초 | 시작·종료 기준, 캐시·네트워크·모델 조건 |

필요한 병목을 측정한 뒤 최적화하고 관련 기능을 다시 확인한다. 기능 구현 중 발생한 크래시·설치 실패·진행 불가는 성능 단계까지 미루지 않는다.
