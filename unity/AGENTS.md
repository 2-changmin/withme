# Unity 작업 지침

## 범위와 기준

- 이 지침은 `unity/` 하위에 적용한다. 실제 Unity 프로젝트는 `withme_frontend/`다. 명령·MCP의 프로젝트 경로를 `unity/` 자체로 지정하지 않는다.
- 답변과 작업 기록은 한국어로 간결하게 작성한다.
- 먼저 `README.md`, `docs/work-plan.md`와 해당 이슈를 읽는다. 필요한 상위 PRD만 추가로 읽는다.
- 사용자의 명시적 지시를 우선한다. 상위 PRD와 실제 코드·API가 충돌하면 차이를 기록하고 임의로 계약을 바꾸지 않는다.
- 에디터 버전은 `withme_frontend/ProjectSettings/ProjectVersion.txt`를 따른다. 임의로 업그레이드하지 않는다.

## 전체 작업 수행

- 전체 구현을 맡으면 `docs/work-plan.md`의 의존 순서대로 이슈를 처리한다. 매 이슈마다 다음 작업 진행 허가를 다시 묻지 않는다.
- 이슈마다 목표·수정 범위·완료 조건을 확인하고 구현 후 관련 검증을 실행한다. 범위 밖 리팩터링과 새 프레임워크 도입을 피한다.
- `구현 완료`와 `사용자 확인 완료`를 구분한다. 기능·빌드·실기기 실행을 확인하지 못했으면 `미실행` 또는 `차단`과 이유를 적는다.
- 사용자 확인을 기다리는 동안 독립 작업은 계속할 수 있다. API·뼈대 등 미정 규격에 의존하는 작업은 목 구현 또는 독립 부분까지만 진행한다.
- 기능 테스트를 먼저 한다. 성능 측정·최적화는 마지막 이슈에서 수행하되, 크래시·무한 루프·실기기 실행 불가는 발견 즉시 수정한다.
- 작업 종료·중단 전 계획표와 이슈 기록을 갱신한다. 다음 실행은 기록과 실제 Git 상태를 함께 확인해 이어간다.

## Git과 에셋

- 아래는 Unity 작업용 기본 규칙이다. 팀 저장소 전체의 기존 브랜치 정책이 정해져 있다는 뜻은 아니다.
- 새 구현 브랜치는 최신 `main`을 기준으로 `codex/unity-<이슈번호>-<작업명>`을 사용한다. 사용자가 지정한 브랜치·초기 등록 순서가 있으면 따른다.
- 사용자 확인 전 `main` 병합을 하지 않는다. 커밋·푸시·PR 생성은 사용자가 맡긴 범위에 맞춰 수행한다.
- 브랜치 전환 전 미커밋 변경을 확인한다. 사용자 변경을 덮어쓰거나 자동으로 버리지 않는다. 다른 작업의 브랜치에 이슈 변경을 섞지 않는다.
- Unity 에셋은 `.meta`와 함께 관리하고 이동·이름 변경 시 GUID를 보존한다. 씬·프리팹은 에디터 API 또는 MCP로 수정하는 것을 우선한다.
- 프로젝트 생성 파일(`Library/`, `Temp/`, `Logs/`, `Obj/`, `UserSettings/`, IDE 생성 파일)과 빌드 결과는 커밋하지 않는다. `git add` 전에 제외 규칙을 확인한다.
- `Assets/`, `Packages/`, `ProjectSettings/`는 관리 대상이다. 큰 바이너리의 LFS 규칙은 첫 추가 전에 확인한다. `.meta`, C#, 텍스트 씬·프리팹을 일괄 LFS 처리하지 않는다.
- Force Text와 Visible Meta Files를 유지한다. 씬·Blender 파일의 변경은 황세인 담당 범위로 취급한다. 다른 담당자는 프리팹·별도 파일로 전달한다.

## 구현과 연결

- 기존 패키지·구조를 재사용한다. Unity 6, URP, uGUI·TextMeshPro, Input System, glTFast를 상위 설계 기준으로 삼는다.
- API와 GLB 연결은 `docs/integration.md`를 따른다. 비밀 키·토큰·개인정보를 소스와 로그에 남기지 않는다.
- 백엔드·Blender·DB 규격 변경이 필요하면 변경 요청을 기록한다. Unity 작업만으로 다른 담당자의 구현을 임의 변경하지 않는다.
- 다른 담당자의 테이블·API 변경은 해당 담당자 리뷰를 받는다. 권한·RLS·업로드 검증·토큰 저장·외부 전송 PR은 장세찬·박재현 2명 승인을 받는다.
- 확정 전 방 진입 금지, 생성 재시작 복구, 동의하지 않은 사용자의 사진 모드·앨범 경로를 지킨다.
- 원본 기록·편집 소리·AI 캐릭터를 구분한다. 실제 등록 소리만 재생하며 돌봄 의무·자유 대화·감정 추론을 추가하지 않는다.

## 완료 보고

- 변경 내용, 실행한 검증과 결과, 미실행 항목·막힌 점, APK 위치와 실기기 확인 순서를 남긴다.
- 자동 검증 통과를 사용자의 시각·조작 확인이나 실기기 성능 통과로 표현하지 않는다.
- MCP를 사용했다는 사실만으로 검증 완료라 하지 않는다. 실제 연결된 프로젝트 경로와 실행 결과를 확인한다.
